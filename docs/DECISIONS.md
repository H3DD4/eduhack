# Decisions (implementation defaults, precedence level 4)

| ID | Decision | Why / alternatives |
|---|---|---|
| D-001 | Python 3.12 via `uv`, FastAPI, SQLAlchemy 2, Alembic, Pydantic v2. | Prompt stack. |
| D-002 | SQLite + local file storage + inline jobs are a **test/no-Docker fallback**. Production path is Postgres+pgvector, MinIO, ARQ. Schemas are translated away on SQLite (`schema_translate_map`). | Fast deterministic tests on any OS; RLS tests run against real Postgres (`TEST_PG_APP_URL`). |
| D-003 | Demo account starts with **no subject**; C01 offers "Use the demo course file" (labeled Demo data) so the 8-state storyboard (G01 empty → C01 → C02 …) runs on the real upload path. `seed --with-subject` pre-creates the ready subject. | Reconciles blueprint storyboard with the prompt's "pre-seeded demo account with a first-year math subject" (SPEC_NOTES conflict 10). |
| D-004 | Next.js rewrites `/api/*` to FastAPI (same-origin) so an httpOnly SameSite=Lax session cookie works; CSRF guard = required `x-thinkfirst-client` header. | Avoids CORS + token storage in JS. |
| D-005 | Initial Alembic revision builds tables from the module models (`create_all`) plus hand-written RLS/trigger SQL; later revisions are autogenerated. | Single source of truth for an initial schema; documented. |
| D-006 | Ids are UUID strings (`String(36)`). | Portable across SQLite/Postgres. |
| D-007 | Password hashing: stdlib `hashlib.scrypt` (n=2^14, r=8, p=1). Sessions: random token in cookie, SHA-256 stored server-side, revocable. | No extra native deps; revocable sessions. |
| D-008 | Google OAuth implemented as a real authorization-code flow when `GOOGLE_CLIENT_ID/SECRET` exist; otherwise the button is replaced by "Google sign-in is not configured" and endpoints return 501. Untested against Google. | Never fake authentication. |
| D-009 | Concept extraction: deterministic heuristic over numbered headings (`1.2 Title`, `F1 Foundation`, `Objective:`, `Prerequisites:`, `Exercise:`) labelled "Heuristic extraction … (no AI used)"; AI proposal only when no structure is found **and** a real provider exists (citations kept only if a verbatim line is found). | Honest, reproducible citations. |
| D-010 | Upload limits = blueprint proposals: 20 MB/file, 5 files/batch, 200 pages/file; audio 25 MB. | Blueprint C01. |
| D-011 | Mock entitlement: 30 units / 30 days; validation bundle = 3 units (explanation, follow-up, transfer) reserved at S01 Start; Professor free-form question = 1 unit; help-ladder steps, SymPy checks and extraction are free. Unused bundle units are released at S03 Finish. Demo-only control to simulate exhaustion. | Exercises Q01 without real payments; numbers are placeholders (OPEN_QUESTIONS Q-06). |
| D-012 | Review date default = today + 3 days, adjustable, labelled "a scheduling hypothesis, not an optimum". One booking per session (idempotent; changing the date reschedules). | Blueprint S03. |
| D-013 | Practice inside a guided session is always labelled **Practised with support** (even with zero hints), because it follows the lesson in the same session; only the no-help transfer can yield **Applied independently (no in-app help)**. Explanations get their own stage label **Explained back**. | Override §3.2 label set; avoids over-claiming. |
| D-014 | Transfer requires correctness + essential coverage + application all *demonstrated* and `mode=independent-transfer` at commit, no reveal, no conversion. | Blueprint "predeclared correctness/coverage/application". |
| D-015 | Transfer novelty: the expression must be symbolically non-equivalent to every practice item, extracted item, and course example, and come with a new context (template families: pens, tiles, tickets). Origin `ai-generated`. | Override §6 demo ("3 packs of (x + 4) pens"). |
| D-016 | Help ladder: 5 levels for `expand` tasks (clarify, strategy, substep, different worked example, confirmed reveal); 3 levels for explanation/transfer tasks (no worked solution exists). Reveal ends the attempt (`ended_assisted`) and creates a fresh generated check. | Override §3.1. |
| D-017 | Follow-up = one question chosen deterministically from the rubric bank for the weakest applicable criterion (priority limits > why > example > coverage > correctness); persisted on the task (`followup_question_id`); retries never reroll. | Blueprint "persist its ID". |
| D-018 | LLM provider order with keys present: Anthropic → Gemini → Groq as fallback chain (`LLM_FALLBACK=true`). Default models: `claude-opus-5-5`, `gemini-flash-latest`, `openai/gpt-oss-120b`. All outputs validated; invalid ⇒ unscored. | User supplied Gemini + Groq keys; keys only in git-ignored `api/.env`. |
| D-019 | STT default `demo`; `STT_PROVIDER=groq` (Whisper large v3, low-confidence segments ⇒ unclear spans) with Gemini fallback, or `gemini`. The local dev `.env` sets `groq` at the user's request; `.env.example` keeps `demo`. | Restrictive default for raw audio (ambiguity policy); user-authorised locally. |
| D-020 | Embeddings: labelled demo hashing embedding (256-d) stored in a pgvector column on Postgres (JSON on SQLite); retrieval ranks in Python per subject. | No embedding key; small corpora. Real embeddings = backlog. |
| D-021 | Tailwind 3.4 with CSS-variable tokens; fonts self-hosted via `@fontsource` packages (OFL 1.1 notices under `web/public/fonts/`). | Stable config; fonts bundled into the build, not loaded from Google. |
| D-022 | Recorder: pure state machine (`web/src/lib/recorder/machine.ts`) + browser adapter; chunks every 1 s to IndexedDB; 10 s command-ack timeout; tab-hidden ⇒ pause; never auto-resume. | Testable; blueprint capture rules. |
| D-023 | Roadmap = semantic ordered lists per unit (vertical spine), concept rows ≥64 px, foundations as optional links under the concepts that list them. No graph view. | Prompt §4. |
| D-024 | Out-of-scope screens (W02, W03, E01–E03, G05, N01 content) render a truthful scope notice naming the milestone. | Blueprint: "truthful scope explanation, not a fake dashboard". |
| D-025 | C02 confirmation navigates to W01 (C03 baseline is optional and reachable at `/subjects/:s/diagnostic`; skip records insufficient evidence). | Storyboard state 3 → 4. |
| D-026 | Local S3-compatible storage uses the SeaweedFS S3 gateway (`chrislusf/seaweedfs`) instead of MinIO: the `minio/minio` (Docker Hub) and `quay.io/minio/minio` images were not publicly pullable on 2026-11-21. Storage code is plain S3 (boto3), so MinIO/AWS S3 drop in via `S3_ENDPOINT_URL`. | Prompt asked for MinIO "S3-compatible"; same API. |
| D-027 | E2E runs against a production Next build (`next build && next start`), not `next dev`: cold dev compiles on a OneDrive-synced Windows folder exceeded assertion timeouts. | Reliable, closer to production. |

## Round 2 (user feedback, 2026-11-21) — explicit user decisions override the blueprint where they conflict

| ID | Decision | Why |
|---|---|---|
| D-028 | Desktop shell (left rail) from **768 px** instead of 1024 px; mobile bar below 768 px. | User: "I need a web app, not mobile". Windows display scaling put typical laptops under 1024 CSS px. |
| D-029 | **Topic-first start (no documents required)**: C01/G01/G02 lead with "What do you want to learn?"; uploads are secondary. C02 shows the generated roadmap with one-click **Start learning** (still editable via "Customize roadmap"). | User request; UC05 generalised from one guided topic to any topic. |
| D-030 | **Concept packs**: per concept, an AI-generated, labelled study pack (lesson, worked example, 2 practice questions with a 5-step help ladder, explain prompt, rubric essentials, follow-ups, transfer task) generated once per concept on the worker; prefetched for the first two levels when a roadmap is confirmed. Generated free-text answers are graded by the LLM grader (uncertain ⇒ unscored; reference answer never echoed); algebraic answers by SymPy. Generic rubrics are upgraded to "AI-generated rubric — not domain-approved". | User: "the app is empty / should be strong, not a demo". |
| D-031 | Game theme: dark expedition sidebar, hero banners, chunky 3-D cards, **visual roadmap map** (winding trail, prerequisite edges, amber side quests, ★ per evidence stage, glowing suggested level) with an accessible List view; course progress rings show *counts* of levels applied without help (not mastery %). No hearts/streaks/leaderboards. | User request, within the ethical-mechanics rules. |
| D-032 | Backend modules named after the user's architecture: `diagnostic`, `adaptation` (moteur d'adaptation), `tutor` + `llm_gateway` (tuteur LLM), `rag`, `student_profile` (renamed from `learner_model`; DB schema name unchanged), `memory` (historique & mémoire), vector store in `rag/vector_store.py`. | User request. |
| D-033 | Vector DB: **pgvector inside Postgres** (project stack, RLS per student) with an optional **FAISS** adapter auto-used when `faiss-cpu` is installed; ChromaDB would plug into the same `VectorStore` interface. Not installed by default (disk constraints). | Prompt stack = pgvector; user diagram names ChromaDB/FAISS. |
| D-034 | **Hybrid retrieval** (`rag.hybrid`): student's own course chunks → shared open library (vector index `knowledge_library.shared_chunks`) → only on a miss, the resource agent fetches live, stores once for **all** users, and re-searches. Live fetch uses the concept/topic name, never the student's answer or question text. | User: "answer locally if data exists, else scrape, store, answer — scales with use". |
| D-035 | The resource agent collects **only openly licensed content** (Wikipedia via MediaWiki API, CC BY-SA 4.0, with attribution/URL/licence stored and shown). It does not scrape course sites or videos; those may only be linked as metadata. | Override §3.8 content rights (robots.txt is not a licence). |
| D-036 | LLM order Groq → Gemini (→ Anthropic) with a 5-minute circuit breaker per failing provider and a 25 s Gemini timeout. | Gemini returned 404/429/60 s timeouts during testing; Groq answered in 3–6 s. |
| D-037 | Adaptive review interval: 1 day (new), 2 days (explained), 4 days (applied without help) — shown with its reason as an adjustable hypothesis. Memory-based nudges ("Last time the factor multiplied only the first term…") and side-quest suggestions after a repeated misconception. | Moteur d'adaptation using the student's own history; no traits. |
| D-038 | **RAG stack = Qdrant + Hugging Face cloud embedder** (user decision). Embedder: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` via HF Inference (384-d, French/English/Arabic in one space, L2-normalised, batches of 32, retries on 429/503). Vector DB: own `qdrant` docker service, collections `course_chunks__<model>_<dim>` (private; payload owner_id/subject_id/revision_id/page; every search filters owner + subject, rows re-checked in Postgres) and `open_library__<model>_<dim>` (shared). Text stays in Postgres. Fallback when HF/Qdrant is unavailable: demo hashing embedder + pgvector/in-memory, with space-specific score thresholds (semantic 0.35/0.40, demo 0.12/0.18). `python -m thinkfirst.modules.rag.reindex` rebuilds collections. | Replaces the demo embedder as the main path; pgvector kept as fallback. |
| D-039 | **Adaptive diagnostic & behavioral tracking architecture (`diagnostic.md`)**: pure, framework-free domain kernel in `thinkfirst/domain/` (`mastery`, `knowledge`, `consent`, `tracking`, `diagnostic`) enforced by `tests/test_architecture.py`; 6 SysBrains (`CORE`, `STUDENT`, `SUBJECT`, `EVIDENCE`, `SESSION`, `PLAN`) communicating through formal `EVENT_CONTRACTS` in `core/events.py`. Non-curated diagnostic items ground their citations via `rag.ground` (Qdrant + HF embedder or fallback) and verify extracted course exercises symbolically with SymPy; completing the diagnostic (`profile.ready`) prefetches AI concept packs on the student's knowledge frontier and seeds the first plan (`plan.updated`). | Scales the 4-module backend with `diagnostic.md` while keeping full backward compatibility with C03/UC07 and the Qdrant+HF RAG stack. |
| D-040 | **Start wizard** (C01, `POST /api/subjects/start`): 4 questions — why (exam / learn something new, optional exam date) → what (topic) → material (several files PDF/DOCX/PPTX/TXT/MD and/or pasted text, or none) → prior knowledge (**test my level** / **start from scratch**). Stored on the subject (`goal`, `exam_date`, `prior_knowledge`); changeable later (`PATCH /subjects/{s}/intent`). Word `.docx` is parsed from `word/document.xml` (no new dependency). | User request: one guided entry for every way of starting. |
| D-041 | **Placement test with AI-written, cross-checked questions** (`modules/diagnostic/placement.py`): 3 MCQs per roadmap concept (easy/medium/hard, each wrong option tagged with a misconception), then an independent second pass (another provider when configured) solves them without the key; only agreeing items are `verified` + `cross_checked` and enter the teammate's adaptive engine (domain rule relaxed: uncalibrated generated items are eligible only when cross-checked, still weighted ×0.5). Curated algebra items stay as they were; without AI the built-in checks are used (labelled). | Replaces the generic "core goal of X" placeholder questions for non-curated topics. |
| D-042 | **Visible level + metrics** (`GET /subjects/{s}/level`): Beginner < 35 ≤ Intermediate < 60 ≤ Advanced < 85 ≤ Expert on `score = 70 % mean estimated mastery + 30 % difficulty-weighted accuracy` (medium ×1.5, hard ×2), shown with the formula; metrics: answers, accuracy, “I don't know”, by difficulty, by unit, per concept (known / partly / to learn + evidence), time per answer, rapid guesses, confidence calibration, detected misconceptions, strengths, gaps. "Start from scratch" = Beginner without a test. | User request ("a lot of metrics, beginner/intermediate/expert"). It deliberately departs from `diagnostic.md`'s "never a score" result screen, on the user's explicit instruction; the teammate's motivating view is still shown next to it. |
| D-043 | **The level drives everything after it**: learner-engine `ConceptSpec.prior` = placement P(L) per concept (clamped 0.02–0.9) or 0.05 for "from scratch" (engine levels 3/4 possible before practice when the prior is high), so practice difficulty (target 0.2 + 0.6·mastery) and next-concept choice start from the measured level; concept packs (prompt v3) and the course summary receive `{level, goal, known, gaps}`. Packs are not prefetched before a pending placement test. | One adaptation path instead of a parallel "level" system. |
| D-044 | **Level-adapted course summary** (`modules/tutor/summary.py`, `tutor.course_summaries` + `course_summary_sections`, RLS): with files, sections follow the files page by page (never crossing files), the model must list the pages it covered, missing pages get one repair pass, and anything still missing is shown as "not covered yet" (never hidden); without files, one detailed section per roadmap concept grounded in open sources. Depth by level (beginner = from scratch, every term defined; expert = compact but complete), exam tips/traps for exam goals. One job per section (parallel-safe). Without AI: a labelled extract of the student's own pages (nothing invented); topic mode unavailable. | User request: "respect the course content, never skip anything"; coverage is checked, not assumed. |
| D-045 | **My path** page (J01, `GET /subjects/{s}/journey`): wizard choices + 4 steps (roadmap → level → summary → learn) with one primary next action; subject tabs gain "My path" and "Summary". The topic launcher now opens the wizard pre-filled. | User feedback: the app was hard to understand. |
| D-046 | **Agentic Tutor engine merged as a backend library** (`api/tutor/`, branch `feat/agentic-tutor`): its separate `/tutor` pages were dropped (duplicate of the start wizard's exam / learn-new paths); its pipeline now feeds the main flow: (1) **heading detection** (Chapitre / Définition / Théorème / II. / 2.1 …) builds the roadmap from the course's own headings when the course does not use "1.2 Title" numbering (`extract.outline_scope`, label "Extracted from your course headings"; with AI the AI proposal wins and the outline is the fallback); (2) **heading-aware chunks** (never cross a chapter/section heading, exact page offsets kept for citations); (3) **HTML uploads** (his parser with BeautifulSoup, standard-library fallback) and a PDF fallback that uses OCR when its optional packages are installed; (4) **answer-key verifier** on placement questions before the cross-check; (5) **course fingerprint + likeness** on concept packs (his integration) and on course-summary sections: the course style is passed to the prompt, a section scoring < 0.70 is rewritten once naming the weak components, the better version is kept and its score is shown ("Matches your course: 82 %"). His Agentic Tutor API (`/api/tutor/...`, now `modules/tutor/tracks/`) and tables (`tutor_tracks` schema, migration 0008_tutor_tracks) are kept; `0009_merge_tutor_tracks` joins the two 0008 branches. | User decision: keep one guided flow, take the agentic extraction/quality pipeline into it. `modules/` keeps exactly 4 folders. |
| D-047 | **LLM gateway hardening**: Gemini falls through to fallback models on 404 (unknown model such as `gemini-4-hydrogen`) as well as 429/503, first-model timeout 40 s; Groq retries 429 up to 3 times with short waits; a rate limit benches a provider for 30 s (other errors 5 min); model JSON is repaired (code fences, text around the object, LaTeX backslashes like \frac / \theta that are JSON escapes). Course summary sections run one after another (each queues the next) with one automatic retry. | Production logs: 6 of 7 summary sections failed (parallel calls → Groq 429 → 5-min bench → Gemini 404 / invalid JSON). |
| D-048 | **"Test my level" order**: wizard → roadmap built → level test → roadmap shown **built on the level** (✓ known from the test, ▶ start here, level banner). Until the test is done the roadmap is locked with "Take the level test" / "Skip — start from scratch"; while questions are being written the test page is still reachable and starts when they are ready. Every subject page has a ← Back button. | User feedback from the mentor demo: the test was not clickable and the roadmap appeared before it. |
